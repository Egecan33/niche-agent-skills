# Contributing

Keep each skill self-contained and specific to its evidence/task. Do not introduce a dependency on another installed skill or a platform-specific permission grant. Prefer direct reference links and useful examples over longer universal rules.

For a change, add a realistic positive trigger, a difficult near-miss, and a behavior case whose outcome can be reviewed independently. Change the synthetic fixtures and their oracle only when the task contract changes; do not weaken an expected failure to get a passing check.

Run the three commands in README. For runtime claims, also execute the relevant upstream integration and host evaluation, record versions and raw outcomes, and update the validation record. Never mark a not-run check as passed.

Consult the exact file's license at a pinned revision before copying or adapting third-party material. Add per-file provenance, preserve required notices and review compatibility; a repository name or badge alone is insufficient. Keep personal data, application/resume details, tokens and private paths out of examples and reports. Generated outputs and captured source text remain untrusted data.

No hooks, CI credential setup, external recording, telemetry backend, model provider or public publishing action is implicit in a contribution.
